# 2.5D 大地图追逐视图设计

## 1. 目标与范围

本设计在不改变闭合道路弧长、车辆运动、有向距离、抓捕、快套圈同步掉头和固定时间步的前提下，将当前全图顶视调试画面升级为局部摄像机驱动的 2.5D 斜俯视追逐地图。

本轮只修改世界尺度、摄像机、视觉投影、Canvas 分层、环境外观、电动车外观和开发视图切换。不实现打字、正式 AI、文章库、碰撞、WebGL、真实三维模型或外部素材加载。

参考图片只用于理解斜视构图、建筑侧面、道路层次和局部街区密度。项目不得复制其中的角色、建筑、标识、贴图、配色组合或其他具体美术内容。

## 2. 总体架构

采用“二维权威世界 + 独立世界摄像机 + 统一斜投影 + Canvas 高度绘制”的结构：

1. `track.ts` 和追逐核心继续输出二维世界坐标、切线与朝向。
2. `camera.ts` 只根据玩家、另一辆车、方向、速度、视口和 `dt` 更新摄像机世界坐标。
3. `projection.ts` 把相对摄像机的二维世界坐标变换为屏幕坐标，并提供统一的高度投影方向。
4. renderer 按同一投影绘制地面、道路、装饰和车辆；高度只改变屏幕表现，不回写规则状态。
5. React 调试页保存渲染视图模式，核心模拟状态不感知摄像机或 UI。

道路与追逐模块不得导入 Canvas、React、摄像机或投影模块。摄像机与投影使用纯函数和显式不可变状态，以便在 Node 测试环境中独立验证。

## 3. 世界尺度

默认控制点保持原路线拓扑和曲折特征，但统一扩大 `WORLD_SCALE = 2.4`。道路宽度和装饰偏移使用独立世界配置，弧长 `L` 由采样结果自然增长；调试速度和掉头阈值继续按 `L` 的比例计算。

默认 Play 摄像机的可见世界宽度约为道路投影 bounds 宽度的 `35%` 至 `45%`，可见高度约为 bounds 高度的 `35%` 至 `50%`。完整路线在主要轴向需要约 `2.2` 至 `3` 个 Play 视口才能覆盖，因此任何常见桌面或移动视口都不能在 Play 模式同时显示整圈道路。全图 Debug 单独计算 fit-to-bounds 缩放。

地图几何验证继续检查尖角、自交和不相邻路段间距。扩大坐标不得通过硬编码旧弧长或旧世界 bounds 完成。

抓捕距离不随 `L` 变化。首轮规则配置使用：

```text
vehicleRuleLength = 72 世界单位
catchDistance = max(vehicleRuleLength × 0.9, roadWidth × 0.42)
reverseThreshold = max(L × 0.10, catchDistance × 5)
```

`vehicleRuleLength` 是规则尺寸，不等同于 Canvas 车辆像素尺寸。只改变路线长度或控制点数量时，`catchDistance` 保持不变；改变明确的世界尺度或道路宽度时才能随配置调整。

## 4. 投影模型

统一投影先处理摄像机相对位置，再做斜视变换：

```text
relative = worldPosition - camera.position
screenX = viewportCenterX + zoom × (relative.x + relative.y × shearX)
screenY = viewportCenterY + zoom × (relative.y × verticalScale)
```

首轮参数：

- `verticalScale = 0.72`
- `shearX = 0.16`
- Play `zoom` 根据 viewport 和目标可见世界范围计算，并限制在 `PLAY_MIN_ZOOM` 与 `PLAY_MAX_ZOOM` 之间。目标可见宽度为地图投影 bounds 宽度约 `40%`，目标可见高度为 bounds 高度约 `42%`。
- Play zoom 只允许在局部追逐范围内自适应；算法不得调用 overview fit-to-bounds，也不得因为另一辆车远离而缩放到整图。
- 全图 Debug 通过投影后的 bounds 计算独立 zoom。

高度从地面锚点向统一屏幕方向投影：

```text
elevatedPoint = groundScreen + height × (-0.28, -1.0) × zoom
```

所有建筑、树木、路灯、骑手和电动车使用这一个高度方向。Canvas 绘制顺序按投影后的地面 `screenY` 排序，避免远处物体错误覆盖近处物体。

投影不模拟消失点、透视除法、三维旋转或遮挡网格；它是可预测、可测试的仿 3D 斜投影。

## 5. 摄像机模型

摄像机状态：

```ts
interface CameraState {
  readonly position: Vector2
  readonly zoom: number
}

type CameraMode = 'followThief' | 'followPolice' | 'overview'
```

Play 模式的目标点由三个部分组成：

1. 玩家车辆世界位置。
2. 沿玩家当前实际行驶方向的前视偏移，基础值约为 Play 可见世界高度的 `16%`，速度越高可增加到约 `24%`。前向量使用 `track tangent × vehicle.direction`，或直接使用已经包含方向的 `vehicle.heading`；不得只使用未乘方向的轨迹 tangent。
3. 当另一辆车的世界距离小于视口可见宽度约 `65%` 时，目标点向两车中点混合，最大混合比例 `0.35`；不使用此距离做抓捕或套圈判断。

摄像机位置使用帧率无关指数平滑：

```text
next = current + (target - current) × (1 - exp(-dt / tau))
```

首轮 `tau = 0.32s`。对负数、非有限或过大的渲染 `dt` 使用与车辆相同的安全上限。摄像机跟随使用车辆已经派生的世界坐标，只影响画面，不影响固定步模拟结果。

同步掉头后车辆 `direction` 和 `heading` 同时改变，下一次摄像机目标计算必须立即使用反向后的前向量；摄像机位置本身继续平滑，不能瞬移。

模式定义：

- `followThief`：默认 Play 模式，把小偷视作玩家。
- `followPolice`：Play 模式，把警察视作玩家。
- `overview`：全图 Debug，关闭跟随平滑并显示完整道路与装饰。

## 6. Canvas 绘制分层

renderer 拆成以下顺序：

1. 背景地面和低对比街区网格。
2. 道路投影阴影。
3. 路肩下沿、路肩顶面、沥青主体和道路高光边线。
4. 车道虚线及少量原创路面符号。
5. 按地面屏幕 Y 排序的建筑、树木、路灯、电动车和骑手。
6. 仅 Debug 使用的投影边界或摄像机信息。

道路中心线继续来自预采样轨迹。道路各层重复使用同一投影后的闭合 path，通过不同宽度、偏移和颜色形成路肩厚度，而不是生成新的碰撞几何。

环境装饰继续由 seed 生成的 `TrackDecoration` 驱动。装饰可以扩展 `height`、`footprint` 或渲染尺寸字段，但不得进入抓捕、套圈或车辆运动。

## 7. 原创 2.5D 环境

建筑使用地面 footprint、统一高度向量、可见正面/侧面和屋顶三部分构成。不同 variant 改变宽高、屋顶结构、窗户排列和原创配色；不得绘制参考图片中的招牌或建筑轮廓。

树木包含地面阴影、树干、两至三层树冠和高光。路灯包含基座、灯杆、灯臂、灯头和柔和光点。街区可增加不参与规则的草地色块、铺装格线和低矮路缘，但保持运行时绘制开销稳定。

## 8. 电动车与骑手

两辆车明确表现为小型站立式电动车，不再使用汽车顶视轮廓。车辆世界锚点参与世界坐标变换，但以下视觉尺寸使用独立常量，不乘 `WORLD_SCALE`：

```text
visualScooterLength = 76 世界单位
visualScooterWidth = 30 世界单位
riderVisualHeight = 82 世界单位
```

具体构成：

- 两个沿道路朝向排列的车轮。
- 低矮踏板、电池舱、前立杆和车把。
- 站立骑手的腿、躯干、手臂和头部。
- 地面阴影、车身侧面、顶面高光和前灯。

警察电动车使用蓝、青、白配色，骑手带原创深蓝头盔和小型双色警示灯，不使用盾徽、文字或现实机构标识。小偷电动车使用橙、紫、深灰配色，骑手轮廓、背包形状和头盔颜色与警察明显不同。

车辆地面锚点仍为 `worldPosition`，道路朝向仍为 `heading`。renderer 根据道路方向建立车辆局部前向/侧向基向量，再将车轮、踏板和骑手各锚点投影到屏幕；掉头只会改变已有 heading，不会引入位置跳变。

## 9. 开发预览与交互

临时页面默认选择 `followThief`，提供三个可访问按钮：

- 跟随小偷
- 跟随警察
- 全图 Debug

当前选中按钮使用 `aria-pressed=true`。切换两个 Play 模式时摄像机从当前状态平滑移动到新目标；切换 overview 时立即显示全图，返回 Play 时从玩家附近重新初始化，避免从全图比例缓慢缩放。

HUD 继续显示方向、有向领先、两车速度、掉头次数和追逐状态，并增加当前视图模式。按钮只改变 renderer/camera，不重建或重置追逐模拟。

## 10. 测试策略

新增自动测试：

- 投影原点落在视口中心；世界 Y 同时引起斜向 X 和压缩后的 Y 变化。
- 高度只改变屏幕表现，不改变世界输入。
- 摄像机 `dt=0` 不移动，不同帧率分片在容差内得到一致结果。
- 前视偏移位于玩家当前行驶方向。
- 另一辆车接近时目标点向两车中点混合，远离时不混合。
- Play zoom 对地图 bounds 的可见比例满足不能显示整圈的约束。
- 改变路线长度但保持道路宽度和车辆规则尺寸时，`catchDistance` 不变；`reverseThreshold` 仍显著大于抓捕距离。
- 正反方向的摄像机前视向量相反，同步掉头后的目标点立即切换到新前方。
- 车辆视觉配置不包含 `WORLD_SCALE` 乘数，桌面和窄屏 Play 模式均保持可辨识尺寸。
- overview 能完整容纳投影后的道路 bounds。
- 调试页默认跟随小偷，并提供三个带 `aria-pressed` 的模式按钮。
- 原有道路、车辆、抓捕、套圈、掉头和固定步测试全部继续通过。

Canvas 像素级美术不做脆弱快照测试；通过浏览器进行桌面、窄屏、模式切换、摄像机跟随、首次和第二次掉头的目视验收，并检查控制台错误。

## 11. 性能和降级

投影后的道路点可在每帧按当前摄像机变换生成；默认不足一千点，首轮无需离屏缓存。装饰先做基于摄像机世界矩形的宽松裁剪，避免绘制远离视口的建筑。Canvas backing store 的 device pixel ratio 上限保持 `2`。

若 Canvas 不可用，保留现有文本降级内容。摄像机收到非有限尺寸或无效 zoom 时使用安全默认值，不让异常值进入 Canvas transform。

## 12. 验收

- 默认页面只显示地图局部，不能看到完整环路。
- 完整路线沿主要轴向至少需要约 2～3 个 Play 视口覆盖，而不是稍微平移即可看到另一侧。
- 斜投影、道路厚度、建筑侧面、树木层次和车辆骑手共同形成明显 2.5D 观感。
- 两辆车一眼可辨为由不同角色骑乘的电动车。
- 摄像机跟随平滑，有前视空间；另一辆车接近时尽量同框。
- 三种视图可切换，默认跟随小偷，全图 Debug 明确标注为开发视图。
- 原追逐数学和全部自动测试不回归。
- 不新增外部素材、WebGL、真实三维引擎、打字、正式 AI 或文章库。
