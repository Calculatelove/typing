# Typing Gaming 产品规格

本文件是 Typing Gaming 唯一有效的产品需求来源。实现、测试、文档和部署不得与本文件冲突。

## 1. 产品定义

Typing Gaming 是纯单人网页打字追逐游戏。游戏只有警察和小偷两个角色，双方驾驶原创简约风格的电动车。玩家控制一方，AI 控制另一方。

- 玩家作为小偷：在文章输入完成之前避免被 AI 警察抓住；文章完成且仍未被抓住则胜利。
- 玩家作为警察：在文章输入完成之前抓住 AI 小偷；文章完成仍未抓住则失败。
- 不实现联网、多人模式、排行榜、账号、服务器或遥测。

## 2. 原创与内容约束

- 产品名称只使用 Typing Gaming。
- 产品 UI、README、代码注释、标识符和资源不得提及作为玩法参考来源的现有产品名称。
- 不下载、复制、临摹或重新打包任何现有游戏的图片、音乐、角色、地图、图标、模型或音效。
- 游戏视觉由 Canvas、CSS 或项目自有 SVG 创建。
- 音效由 Web Audio API 合成；只有具有明确许可的原创资源才可作为例外。
- 不使用来源或许可证不明的第三方素材。
- 第三方工程依赖不得捆绑为游戏内容。

## 3. 技术架构

- 构建工具：Vite。
- UI：React、TypeScript 和 CSS。
- 游戏场景：HTML Canvas。
- 测试：Vitest；后期增加少量真实浏览器冒烟测试。
- React 负责设置、文章区域、HUD 和结果页。
- Canvas 负责地图、道路、建筑装饰、车辆、摄像机和追逐动画。
- 道路、车辆、追逐、速度、AI 和状态机必须是与 React、DOM、Canvas 解耦的 TypeScript 模块。
- 核心游戏逻辑优先使用纯函数、显式状态和可注入的时间及随机源。
- 模拟使用固定时间步，渲染帧率不得改变规则结果。

## 4. 开局设置

开始游戏前允许玩家选择：

- 身份：警察或小偷。
- 语言：英文或简体中文。
- 难度：简单、普通、困难或影子。
- 文章长度：短、中或长。
- 文章：指定文章或从当前语言及长度筛选结果中随机选择。
- 按键音开关。
- 错误提示音开关。

## 5. 游戏状态机

主状态为 `setup`、`ready`、`running`、`won` 和 `lost`。

- `setup`：选择本局设置。
- `ready`：地图、文章和车辆初始化完成；车辆和计时冻结；输入入口聚焦。
- 玩家第一次产生正确有效输入时，由 `ready` 进入 `running`。
- `running` 中发生终局事件后进入 `won` 或 `lost`，模拟冻结。
- 结果页允许以相同配置重试，或返回设置页。

胜负规则：

| 玩家身份 | 抓捕发生 | 文章完成且未抓捕 |
|---|---|---|
| 小偷 | 失败 | 胜利 |
| 警察 | 胜利 | 失败 |

输入事件与模拟使用同一单调时间线。抓捕和文章完成发生在同一时间精度内时，抓捕优先。终止状态不得被后续事件改写。

页面进入后台时暂停模拟时钟并丢弃过长积压，返回页面时不得发生位置跃迁。

## 6. 地图和环形道路

道路是较大、封闭、曲折的原创环状道路，不使用简单圆形或椭圆。道路由闭合 Catmull–Rom 控制点生成，构建阶段密集采样并建立累计弧长查找表。

道路数据至少包含：

- 控制点、道路宽度和总弧长 `L`。
- 每个采样点的弧长、二维位置、单位切线和单位法线。
- 世界边界、装饰随机种子和纯渲染装饰。

`sampleAt(s)` 将任意正负弧长规范到 `[0,L)`，再通过弧长查找表插值世界坐标和朝向。地图构建必须检查首尾连续、过尖转角、道路自交和不相邻路段间距。

建筑、路灯、树木和街区形状为原创简约装饰，不参与碰撞或胜负判断。

## 7. 车辆和追逐距离

每辆车的权威状态包括角色、环形弧长位置、非负实际速度和目标速度。二维坐标与朝向从道路采样派生，不作为规则权威状态。

双方始终同向行驶并同时掉头，因此世界状态只保存一个 `direction ∈ {+1,-1}`。

安全取模：

```text
mod(x, L) = ((x % L) + L) % L
```

位置更新：

```text
s' = mod(s + direction × speed × dt, L)
```

小偷沿当前方向领先警察的距离：

```text
lead = mod(direction × (thiefPosition - policePosition), L)
```

`lead` 接近零表示小偷在警察前方且可能被追上；`lead` 接近 `L` 表示小偷接近领先整圈。抓捕、套圈和掉头禁止使用二维欧氏距离。

## 8. 快套圈掉头和抓捕

参数满足：

```text
0 < catchDistance < reverseThreshold < L / 2
reverseThreshold >= 5 × catchDistance
```

首轮调参范围：`catchDistance` 为 `0.5%L` 至 `1.5%L`，`reverseThreshold` 为 `8%L` 至 `12%L`。

当小偷比警察快，且 `lead` 从下方穿越 `L - reverseThreshold` 时：

1. 在固定时间步中求出阈值穿越时刻。
2. 将双方推进到该时刻。
3. 原子执行 `direction = -direction`。
4. 保持双方弧长位置不变，避免世界坐标瞬移。
5. 使用新方向完成本时间步剩余部分。

掉头只响应阈值穿越，并结合 cooldown、hysteresis 和 armed 状态防止连续反复触发。

抓捕只在 `lead` 从大于 `catchDistance` 向下穿越阈值、警察相对小偷正在接近、且没有更早掉头事件时发生。一个固定步内可能发生规则事件时必须求穿越时刻，不能只检查步末位置。

核心模拟初始使用 60 Hz 固定步长，并限制每帧最大补算步数。

## 9. 输入和中文 IME

英文和中文统一通过保持焦点的原生 `textarea` 接收，React 独立渲染文章进度。中文输入不得依靠 `keydown` 获取字符。

- `compositionstart` 进入组合状态。
- `compositionupdate` 和组合期间的 `input` 不计分。
- `compositionend` 只结束组合状态。
- 随后的第一个 `isComposing=false` 的 `input` 处理正式提交文本。
- 浏览器缺少最终 `input` 时，以微任务消费尚未处理的缓冲作为降级。
- 每个缓冲版本最多消费一次，防止重复计数。

文章和输入统一进行 NFC 规范化，并优先使用 `Intl.Segmenter` 的 grapheme 模式。fallback 按 Unicode code point 遍历；文章库不得使用会令 fallback 产生明显差异的 Emoji、组合字符或异常控制字符。

一次提交多个 grapheme 时逐个比较：正确前缀推进，首个错误产生一次错误事件，其后的本次提交内容丢弃，已有正确进度不回退。粘贴、拖放、自动更正、自动大写和拼写替换关闭。

## 10. 玩家动态速度

玩家速度不得由文章总进度决定。维护最近约三秒的正确计分 grapheme 时间戳。

设窗口 `W=3s`，窗口内正确单位数为 `N`，观测时长为：

```text
D = max(1s, min(3s, now - runningStartedAt))
```

英文表现率：

```text
performanceRate = (N / 5) × (60 / D)
```

中文表现率：

```text
performanceRate = N × (60 / D)
```

英文计分单位包含必须输入的字母、标点和空格；中文包含必须输入的汉字和标点。文章长度验证必须复用正式计分规则。

初始基础速度映射：

```text
baseSpeed = (L / 90s) × (performanceRate / 50)
targetSpeed = baseSpeed × comboMultiplier × errorPenalty × idleMultiplier
```

- 表现率计算上限约 140。
- 连击倍率从 `1.0` 渐近增长到不超过 `1.10`，错误或明显空闲时重置。
- 错误瞬间将惩罚倍率降到约 `0.55`，约 `0.7s` 指数恢复。
- 最后一次正确输入约 `0.75s` 后开始空闲衰减，连续空闲约 `4s` 后速度归零。
- 应用全部倍率后的速度上限初始约为 `L/34s`。

实际速度使用帧率无关指数平滑：

```text
actual += (target - actual) × (1 - exp(-dt / tau))
```

加速时间常数初始为 `0.25s` 至 `0.35s`，减速为 `0.10s` 至 `0.18s`。所有数值集中配置并在模拟阶段校准。

## 11. AI 难度

四档难度共用一个 AI 控制器，只通过参数改变行为。AI 和玩家使用相同的表现率到基础车辆速度映射。普通三档使用带种子的随机源，正式局记录 seed 以便复现。

| 难度 | 每局平均表现率 | 常规波动 | 目标更新间隔 | 临时行为 |
|---|---:|---:|---:|---|
| 简单 | 25～35 | 约 ±5 | 1.2～2.5 秒 | 较明显停顿或降速 |
| 普通 | 40～55 | 约 ±3 | 2～4 秒 | 少量轻微变化 |
| 困难 | 60～80 | 约 ±2 | 3～5 秒 | 偶发 5%～10% 短加速 |
| 影子 | 玩家过去五秒 | ±2%～3% | 固定五秒 | 无随机停顿和强加速 |

影子模式只读取已经发生的五秒历史，每五秒更新一次目标；历史不足时使用中性初始值 45。AI 不得读取目标字符、剩余文章、未来输入或未来文章状态。

## 12. 文章库

- 英文短、中、长各 20 篇，共 60 篇。
- 中文短、中、长各 20 篇，共 60 篇。
- 总计 120 篇。

| 档位 | 50 表现率预计时长 | 英文词数 | 中文计分 grapheme |
|---|---:|---:|---:|
| 短 | 约 2 分钟 | 90～110 | 90～110 |
| 中 | 约 4 分钟 | 190～210 | 190～210 |
| 长 | 约 6 分钟 | 290～310 | 290～310 |

每篇文章包含 `id`、`title`、`language`、`length`、`text`、`scoredGraphemeCount`、`wordCount`、`estimatedSecondsAt50`、`sourceType`、`sourceLabel`、`sourceUrl`、`license` 和 `tags`。

文章优先全部编写为原创练习文本。只有能可靠确认公共领域或开放许可证时才允许加入外部内容，并完整记录来源 URL 和许可证。随机选择必须先按语言和长度筛选，不能越过筛选范围。

## 13. UI、Canvas 和音频

- 设置页提供全部开局选项。
- 游戏页显示 Canvas、文章输入进度和 HUD。
- HUD 至少显示身份、难度、实时表现、目标速度、实际速度、连击、错误和文章进度。
- 结果页显示胜负、统计、重试和返回设置。
- Canvas 使用原创简约城市道路风格，车辆和装饰不得使用外部美术素材。
- 音效通过 Web Audio API 合成，并遵守按键音和错误音独立开关。
- 页面需要键盘可用、清晰焦点、可读对比度和响应式布局。

## 14. 测试与质量门禁

自动测试至少覆盖：

- 道路闭合、弧长、正反方向和跨越零点。
- 抓捕、快套圈、一次掉头、坐标连续、防抖和固定步事件穿越。
- 英文输入、中文 composition 顺序、批量提交、grapheme 和重复事件。
- 三秒窗口、稳定表现率、burst、连击、错误、空闲、速度上限和帧率独立性。
- 四档 AI 参数、统计范围、seed 复现、影子历史公平性。
- 两种身份胜负、同刻抓捕优先和终止幂等。
- 文章数量、唯一性、长度、来源、Unicode 和筛选随机性。
- GitHub Pages `/typing/` 子路径和浏览器基本流程。

每轮完成前必须运行：

```text
npm test
npm run typecheck
npm run lint
npm run build
```

真实中文 IME 最终在 Chrome、Edge 和 Safari 手工验收。

## 15. 部署

- 部署目标为 GitHub Pages 项目站点 `https://calculatelove.github.io/typing/`。
- Vite production base 固定为 `/typing/`。
- 所有静态资源通过 Vite import 或 `import.meta.env.BASE_URL`，禁止硬编码 `/assets/...`。
- 使用 GitHub Actions 构建并部署 `dist`，不提交 `dist`。
- 工作流在 `main` push 和手动触发时运行 test、typecheck、lint 和 build，然后上传 Pages artifact 并部署到 `github-pages` environment。
- 部署权限遵循最小权限，并防止并发部署相互覆盖。

1. 工程骨架、长期约束、唯一产品规格、占位页和质量命令。

8. 自动玩家模拟、数值平衡和极端场景测试。

10. CI、GitHub Pages 部署和线上验收。

## 17. 最终验收

- 两种身份和四档难度均能完整游玩并正确判定胜负。
- 英文输入与中文 IME 不漏记、不重复计分。
- 玩家速度由最近约三秒表现驱动，AI 不读取未来信息。
- 抓捕、跨零点、快套圈和掉头在正反方向均正确。
- 120 篇文章通过数量、长度、来源和唯一性验证。
- 产品没有联网、账号、服务器、遥测或排行榜。
- 所有视觉和声音符合原创约束。
- 自动检查全部通过，GitHub Pages 子路径下无静态资源 404。
